# Working in kriging-rs

Orientation for coding agents (and humans in a hurry). Rust geostatistics core, a
wasm-bindgen layer, a TypeScript facade published as `kriging-rs-wasm`, and two web apps.

## Layout

| Path | What it is |
|------|------------|
| `src/` | Rust crate. `variogram/` (models, empirical, fitting), `kriging/` (2-D lat/lon models, 3-D models, shared `solver.rs`), `projected.rs` (planar x/y), `spacetime/`, `cokriging/`, `simulation*.rs`, `cv*.rs`, `gpu.rs` (WGSL kernel). |
| `src/wasm/` | wasm-bindgen exports (`mod.rs` for 2-D, `spacetime.rs`, `three_d.rs`, `cokriging.rs`). Variograms cross the boundary as one `VariogramSpec` object (`src/variogram/spec.rs`). |
| `npm/kriging-rs-wasm/` | TS facade over the raw exports: `src/internal/wasm-shapes.ts` (raw signatures), `src/types.ts` (public option/result types), one module per area, `src/index.ts` (the export list). README is the user guide. |
| `examples/web-2d/` | **The template for a new web app**: typed Vite starter, kriging in a Web Worker, planar data. Copy from here. |
| `www/` | Older React demo (lat/lon). Fine for browsing features; do not copy its `lib/variogram.js` (Euclidean distance on raw degrees) or its north-first grid. |
| `tests/` | Rust integration and parity tests. `tests/parity_3d/fixtures/generate_textbook_kriging.py` regenerates the textbook references. |

## Commands

```bash
# Rust (toolchain pinned in rust-toolchain.toml)
cargo test                                  # default build: Real = f32
cargo test --features f64
cargo fmt --all -- --check
cargo clippy --all-targets --features "f64,wasm" -- -D warnings
cargo clippy --all-targets --features "gpu,gpu-blocking,wasm" -- -D warnings   # f64 and gpu are exclusive

# WASM package (needs `rustup target add wasm32-unknown-unknown` and wasm-pack)
cd npm/kriging-rs-wasm
npm ci && npm run build        # wasm-pack -> pkg/, tsc -> dist/
npm run verify                 # contracts typecheck, lint, build, smoke (2-D + 3-D), vitest
npm run format:check           # prettier; CI does not run it, keep it clean anyway

# Web apps (after the package is built)
cd examples/web-2d && npm ci && npm run build && npm run check
cd www && npm ci && npm run build
```

CI (`.github/workflows/ci.yml`) runs fmt, clippy and tests for both feature sets, builds the
wasm target, runs `npm run verify`, and builds both web apps.

## Adding or changing a WASM-exposed API

1. Rust core in `src/` with unit tests (write the failing test first; see
   `.cursor/rules/rust-tdd.mdc`).
2. Export in `src/wasm/*.rs`. Take variograms as `variogram: JsValue` via
   `variogram_model_from_js`. Map errors with `kriging_err_to_js` / `coded_err` so JS gets a
   stable `code`. Planar input goes through `PlanarOrigin` and 3-D through `Origin3D`
   (centre in f64 before narrowing to `Real`).
3. Add the raw signature to `npm/kriging-rs-wasm/src/internal/wasm-shapes.ts`, then a typed
   wrapper (options object in, `wrapThrown` around the raw call), option/result types in
   `types.ts`, and exports in `index.ts`.
4. Add a vitest case in `tests/integration.test.ts` and document it in the npm README.
   Nothing checks `wasm-shapes.ts` against the generated `pkg/kriging_rs.d.ts` (the raw
   module is cast to `RawModule`), so a wrong argument order or type only shows up at
   runtime. The vitest case is the real check. `typecheck:contracts` only type-checks
   public-API usage in `tests/contracts.ts`.

## Conventions and invariants

- **Real is f32 by default.** Accumulate in f64 where it matters. `clippy::unnecessary_cast`
  is allowed only under the `f64` feature for exactly this reason.
- **Variograms:** `sill` is the total sill. `γ(0) = 0` exactly and the nugget is the jump at
  0⁺, so `covariance(0) = sill` and the nugget sits on every kriging diagonal. Kriging
  variance includes the nugget. Do not reintroduce `γ(0) = nugget`.
  `larger_nugget_raises_kriging_variance_in_every_path` guards this.
- **Units:** lat/lon APIs use Haversine kilometres. Projected and 3-D APIs use the
  coordinates' units.
- **Angles:** 2-D `majorAngleDeg` / `azimuthDeg` are counter-clockwise from +x. 3-D
  (`ang1`, 3-D `azimuthDeg`) follow GSLib: clockwise from north, dip positive down.
- **Grids:** `predictGrid` (lat/lon and projected) returns row 0 = south. Canvas row 0 is
  the top. Flip once (see `toNorthUp` in `examples/web-2d/src/core.ts`).
- **Parity fixtures** are regenerated by the in-repo generator. If a parity test fails,
  diagnose before regenerating; the fixtures once encoded a bug.
- **TS API style:** one options object per call, `free()` / `[Symbol.dispose]` on models,
  `KrigingError` with a `code` for every failure.

## Gotchas

- A Node consumer must pass the wasm bytes to `init()`. Locate them with
  `import.meta.resolve("kriging-rs-wasm/wasm")`. `init()` with no argument only works where
  `fetch` can load the file (browsers and workers).
- On Windows, `process.exit()` right after a failed `fetch` can trip a libuv assertion in
  child-process tests. Set `process.exitCode` instead.
- `node_modules/kriging-rs-wasm` in the web apps is a `file:` link to the package, so
  rebuild the package (`npm run build` in `npm/kriging-rs-wasm`) after changing Rust or TS.
